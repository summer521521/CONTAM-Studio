# 风险登记表

级别表示当前相对优先级，将随技术Spike和真实样例证据调整。

| 风险 | 影响 | 当前级别 | 缓解方向 | 验证阶段 |
|---|---|---|---|---|
| PRJ回写破坏文件 | 用户项目损坏或无法被官方工具读取/求解 | 极高 | 默认不覆盖原始文件；草稿、快照、结构检查和回归样例 | Phase 2-3 |
| 未知内容静默丢失 | 复杂项目语义改变且用户不知情 | 极高 | 未知区块保留；不能可靠保存时只读；保存前后确定性比较 | Phase 2-3 |
| CONTAM编号重排造成引用错误 | Zone、路径、源汇或控制引用错配 | 极高 | 内部稳定UUID；显式编号映射和引用完整性检查 | Phase 2-4 |
| AI绕过审批 | 未授权修改、运行或数据发送 | 极高 | 默认只读；Patch、Diff、验证、确认和最小权限 | Phase 6-7 |
| 运行结果无法追溯到输入快照 | 研究结果不可复现或被错误归因 | 高 | 不可变快照、运行清单、求解器与输入输出哈希 | Phase 4-5 |
| ContamX版本和许可处理不清 | 分发阻塞、合规风险或结果差异 | 高 | 核对官方资料；记录版本与来源；维护第三方声明 | Phase 4、Beta |
| 范围膨胀 | 核心闭环长期无法完成 | 高 | 阶段退出条件；明确非目标；复杂对象先只读 | 全阶段 |
| 过早引入复杂架构 | 维护成本超过实际价值 | 中高 | 暂不建微服务、插件或多求解器抽象；用Spike证明需要 | Phase 1-4 |
| 单人维护压力 | 关键知识集中、迭代和支持中断 | 高 | 小步交付、决策记录、自动化回归和清晰所有权 | 全阶段 |
| 中英文术语不一致 | 教学误解、搜索困难和结果解释偏差 | 中高 | 建立双语术语表；以官方术语为基准；专家复核 | Phase 1-2、Beta |
| Windows打包和依赖兼容风险 | 用户无法安装、启动或找到求解器 | 高 | 早期目标机Spike；固定依赖；验证sidecar与安装方案 | Phase 1、Phase 4、Beta |
| Python运行时发现或打包失败 | 桌面界面可启动但无法读取PRJ | 高 | 开发期只允许显式路径或项目`.venv`；安装包前验证冻结、签名、升级和诊断 | Phase 2、Beta |
| Tauri-Python协议漂移 | 字段被错误解释、旧响应覆盖状态或错误失真 | 高 | 协议版本、`request_id`、双端schema校验和跨语言回归测试 | Phase 2-5 |
| 子进程挂起、崩溃或输出泛滥 | 界面长时间等待、内存增长或主进程不稳定 | 高 | 一次性进程；读取/计划10秒、应用15秒超时；终止、并行排空和stdout/stderr上限 | Phase 2-5 |
| 文件路径与诊断泄露项目隐私 | 本地路径或项目内容出现在界面、日志或报告 | 中高 | Rust拥有文件选择；响应路径一致性检查；跨IPC前清理message和context；前端二次清理；不传Traceback、命令或文件内容 | Phase 2-7 |
| Patch计划后源文件或目标位置变化 | 旧Patch写入错误Zone、错误字段或错误快照 | 极高 | 绑定源SHA-256、大小、读取模式、文件头、Zone编号、行号、旧记号和字节范围；应用时全部重验 | Phase 3-7 |
| 副本写入覆盖既有成果或留下未验证文件 | 用户已有文件丢失，或错误副本被误认为成功 | 极高 | 仅允许不存在的新`.prj`；独占创建；写后字节与语义验证；失败清理 | Phase 3-7 |
| WebView伪造路径或Patch绕过审阅 | 写入非用户选择位置，或应用未经验证的字节范围 | 极高 | 路径只由Rust原生对话框取得；完整Patch仅存Rust内存；前端只提交session和`patch_id` | Phase 3-7 |
| 旧项目session或旧Patch被竞态复用 | 修改应用到后来打开的项目或覆盖较新状态 | 极高 | 单操作门闩；session和`patch_id`双重验证；打开新项目和成功应用时清除旧Patch | Phase 3-7 |
| ContamX求解器版本或架构识别错误 | 运行结果不可复现或误执行未知程序 | 高 | 只接受显式绝对路径；固定文件名、大小、SHA-256、Windows版本、PE架构及受限`--Version`证据，全部一致后才执行 | Phase 4、Beta |
| 求解器运行生成物未完整追踪 | 结果无法审计，或输出污染源项目目录 | 高 | 禁止run_root位于源目录树；输入三方快照验证；源目录文件/子目录清单；全部生成物逐项记录哈希、大小和相对路径 | Phase 4-5 |
| 求解器流捕获或超时终止证据不完整 | 失败运行被误判成功或缺少审计证据 | 高 | 白名单子进程环境；捕获线程错误传播；join状态检查；终止失败结构化诊断；运行后保留失败manifest | Phase 4、Beta |
| ContamX进程树残留或超时 | 资源泄漏、后台进程继续写入或桌面无响应 | 中高 | 固定超时、终止进程、保留失败manifest；后续验证Windows Job Object治理 | Phase 4、Beta |
| SimRead版本或输出契约漂移 | 结果字段解释错误或无法复现 | 高 | 固定官方工具哈希、版本、PE架构和严格表头；未知契约整体拒绝 | Phase 5A |
| 结果脱离Phase 4输入快照 | 结果无法追溯或误读其他SIM | 高 | 只接受成功manifest，复制前后校验PRJ/SIM哈希并记录提取manifest | Phase 5A |
