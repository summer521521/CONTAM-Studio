## 2.执行角色与状态

### 2.1执行角色

| 标记 | 执行者 | 规则 |
|---|---|---|
| `L` | 低思考强度模型 | 规格已冻结，可严格逐步实现；不得改变目标或扩范围。 |
| `H` | 高思考强度模型 | 涉及并发、文件身份、进程树、跨语言协议、数据生命周期、许可或产品取舍；先形成规格，再交`L`实现。 |
| `U` | 用户 | 需要产品选择、许可决定、真实GUI、干净机器或用户研究证据。 |

`H→L`表示高思考模型先冻结ADR、接口和测试条件，低思考模型只能按冻结规格编码。任何`U`任务都不能由模型伪造为通过。

### 2.2任务状态

- `ready`：前置任务和门禁均已完成，可以执行。
- `blocked`：等待前置任务、用户证据或高思考规格。
- `in_progress`：本次只允许一张任务卡处于该状态。
- `automated_verified`：规定的自动检查通过，但不代表GUI、安装或用户验证通过。
- `pending_user`：实现和自动检查已完成，等待用户手动验收。
- `completed`：本卡规定的全部自动与人工证据均已满足。
- `hold`：当前禁止开始。

## 11.立即升级条件

以下事项不得由低思考模型自行判断或实现：

- 新增运行时依赖、Windows API crate、测试框架、冻结器或安装器插件。
- 任何PRJ未知语法、编码、续行、编号、跨区段引用或完整AST设计。
- 文件原子性、所有权、TOCTOU、junction/symlink、跨卷和删除语义。
- 进程树、Job Object、取消、超时预算、锁顺序和迟到结果。
- 跨语言协议含义、版本迁移、数据存储迁移和持久化身份。
- ContamX、SimRead、CVODE、样例、项目许可证、签名和分发法律结论。
- 扩大Tauri capability、WebView路径/文件/网络/Shell权限或管理员权限。
- AI写入、多Patch事务、引用完整性、自动运行或任何新工具权限。
- 用户文件归属不清、需要删除唯一证据、需要读取凭据或修改系统/`.codex`配置。

遇到这些条件时，正确结果是停止、保留工作树、写清已知证据和未决问题，而不是选择一个看似可行的默认答案。
