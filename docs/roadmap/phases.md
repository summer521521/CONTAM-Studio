# 阶段路线图

路线图不承诺未经验证的工期。每一阶段都应形成可独立验证的纵向切片，并保持此前安全边界。

## Phase 0：项目文档与仓库基础

- **目标**：固化产品范围、架构方向、安全边界和仓库规则。
- **主要交付物**：README、项目规则、范围与架构文档、风险登记表、ADR、私有Git仓库。
- **退出条件**：文档链接有效，边界一致，单一基础提交已推送到`main`。
- **不包含**：技术栈初始化、依赖安装或任何业务功能。

## Phase 1：现代GUI空壳

- **目标**：验证Windows桌面工作台的最小界面与双语框架。
- **主要交付物**：Tauri/React空壳、基础布局、语言切换和最小权限配置。
- **退出条件**：桌面应用可在目标Windows环境启动，核心布局和中英文切换可验证。
- **不包含**：PRJ解析、项目写入、ContamX运行和AI。

## Phase 2：读取并显示第一个真实Zone

- **目标**：从真实PRJ安全读取一个Zone并显示来源信息。
- **主要交付物**：最小只读文件入口、受限领域模型、Zone检查视图和测试夹具。
- **退出条件**：真实样例中的首个Zone可重复读取，原文件未修改，未知内容未被宣称支持。
- **不包含**：保存、编号重排、完整PRJ解析和求解。
- **当前进展**：Phase 2A验证contamxpy隔离稳态初始化边界；Phase 2B建立严格CONTAM 3.4简单Zone纯文档读取器；Phase 2C已通过原生文件选择器、一次性Python JSON桥和桌面工作台展示三个官方样例的全部Zone。此进展只覆盖严格格式子集，不扩大为完整PRJ兼容。

## Phase 3：第一次安全修改

- **目标**：对一个受支持属性完成草稿内修改和受控保存闭环。
- **主要交付物**：稳定UUID、结构化Patch、Diff、验证、确认、快照和撤销入口。
- **退出条件**：修改只作用于副本或草稿，保存前后检查可重复，原始PRJ默认不覆盖。
- **不包含**：复杂引用、全格式无损回写和批量编辑。
- **当前进展**：Phase 3A-0已在Python核心实现哈希绑定、仅写新副本的单Zone `volume_m3` Patch。Phase 3B进一步建立Rust内存session、完整Patch保管、前端安全审阅视图、单行Diff和原生“另存为新副本”流程；前端不能提交路径或完整Patch，应用成功后切换到新副本。尚未建立稳定UUID、快照、撤销、多Patch、其他字段或完整PRJ保存，因此Phase 3仍未整体完成。

## Phase 4：第一次真实ContamX运行

- **目标**：使用官方ContamX运行一个明确的项目快照。
- **主要交付物**：求解器发现、受控运行工作区、运行清单、日志和失败处理。
- **退出条件**：输入快照、求解器版本和输出可追溯，失败不会破坏用户项目。
- **不包含**：重写求解算法、复杂批量调度和其他求解器。
- **当前进展**：Phase 4A已在Python核心完成NIST官方ContamX独立运行工作区、输入快照、求解器版本/哈希记录、stdout/stderr证据、生成物清单和成功/失败manifest。真实Windows x64运行已验证官方`test_GetPrjInfo.prj`并产生非空SIM；尚未接入GUI、读取结果值或实现批量运行。

## Phase 5：读取第一个真实结果

- **目标**：从Phase 4的真实运行中读取并呈现一个确定性结果。
- **主要交付物**：最小结果读取器、结果元数据、表格或曲线视图和导出验证。
- **退出条件**：结果可追溯至运行清单和输入快照，并与参考输出核对。
- **不包含**：完整结果工作台、所有结果格式和高级可视化。

## Phase 6：只读AI助手

- **目标**：让用户主动配置的AI解释已披露范围内的只读上下文。
- **主要交付物**：提供方配置、上下文预览、只读工具、推测与确定性结果标识。
- **退出条件**：AI无法写入项目或启动求解，用户能看见其读取范围和联网状态。
- **不包含**：Patch应用、自动运行和完全自主Agent。

## Phase 7：AI Patch与审批

- **目标**：让AI通过统一领域接口提出可审查修改。
- **主要交付物**：结构化Patch、Diff、确定性验证、用户确认、快照和审计记录。
- **退出条件**：AI不能直接编辑原始PRJ或绕过审批，拒绝和回滚路径均可验证。
- **不包含**：无审批写入、任意命令执行和完全自主Agent。

## Beta稳定化与真实用户试用

- **目标**：用真实教学和科研场景验证可靠性、可理解性与分发边界。
- **主要交付物**：回归样例、安装包验证、用户反馈、关键缺陷修复和许可声明材料。
- **退出条件**：目标用户完成核心闭环，P0缺陷关闭，数据安全与运行追踪经真实案例验证。
- **不包含**：企业平台、多求解器、插件市场、云协作或跨平台正式发行。
