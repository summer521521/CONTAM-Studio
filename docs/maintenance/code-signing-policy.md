# 代码签名策略

## 0.1.0状态

0.1.0采用透明的未签名发布：安装包没有Authenticode发布者证书，Windows可能显示“未知发布者”或SmartScreen提示。项目不会用自签名证书冒充公共信任。

可信度由公开源码、Apache-2.0许可证、固定Git标签、Windows CI、SHA-256清单、发布资产审计和GitHub Sigstore发布核验共同提供。GitHub证明不替代Authenticode。

## 免费签名路线

项目公开发布并形成维护记录后，申请SignPath Foundation开源代码签名。申请和后续签名必须满足：

- 源码、许可证、发布历史和构建说明公开；
- 仓库账户启用MFA；
- 生产二进制能够绑定源码提交和发布工作流；
- 每个签名请求经维护者人工批准；
- 私钥、证书口令和签名服务凭据不得进入仓库。

获批前保持资产名称、清单和Release说明中的`unsigned`事实。获批后从新版本开始签名，不覆盖0.1.0既有资产。
