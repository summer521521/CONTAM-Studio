# ADR-004：分离PRJ文档读取与仿真执行

## 状态

已接受。

## 背景

Phase 2A验证了contamxpy 0.0.9可通过公开API取得真实Zone信息，但其入口需要调用`setupSimulation(1)`执行稳态初始化，并会生成仿真相关文件。损坏或不兼容的PRJ还可能令原生进程访问冲突。临时副本、独立目录和一次性进程能够保护源文件、隔离崩溃及生成物，却不能把该过程变成无副作用的文档读取，也不构成权限沙箱。

项目打开需要快速、可诊断且不启动仿真的文档读取职责；仿真执行则需要明确快照、运行目录和结果追踪。若两者共用同一原生入口，GUI打开文件会隐式触发计算并扩大失败影响。

## 决策

- PRJ文档读取与ContamX仿真执行是两个独立职责，分别设计接口、错误语义和生命周期。
- contamxpy归入隔离的仿真执行与结果验证接口，不作为纯PRJ文档解析器。
- GUI不得直接调用contamxpy原生入口；未来调用必须经过受控领域接口和独立执行边界。
- 项目打开流程需要独立的只读PRJ文档读取器。首期只支持有官方文档和真实样例共同验证的格式子集，并对不支持的版本、字段和记录明确拒绝。
- 未知区块和未知记录必须保留为“未知/未支持”状态，不得静默忽略或把部分读取误报为完整理解。
- 当前不实现PRJ保存、回写、编号重排或未知内容重建。
- ContamX仿真执行继续使用已验证哈希的临时副本、独立运行目录、一次性进程和结构化诊断，并将输出绑定到明确输入快照。
- 一次性进程只用于隔离原生崩溃和生成物，不得描述为权限沙箱，也不能用于处理不受信任的恶意PRJ。

## 理由

- 打开文档不应隐式执行稳态初始化或产生仿真结果。
- 独立读取器可按证据逐步扩大支持范围，并对未知内容诚实降级。
- 隔离执行边界仍可复用官方ContamX承担数值求解，同时限制原生崩溃和生成物的影响范围。
- 明确职责能避免GUI、AI或未来服务绕过统一验证和运行追踪。

## 后果

- Phase 2需要先实现严格受限的只读文档读取切片，再考虑与GUI连接。
- 读取器支持范围会小于完整PRJ格式；遇到未知内容时必须返回结构化诊断或保持只读。
- 读取结果与仿真验证结果需要区分来源，不得把ContamX执行输出当作文本格式定义。
- 后续仍需维护独立的仿真工作目录、进程管理、超时、清理和诊断逻辑。
- 在无损回写证据建立前，应用只能读取已验证子集，不能据此保存整个PRJ。

## 替代方案

- **继续以`setupSimulation(1)`作为项目打开入口**：会隐式执行计算、生成文件并暴露原生崩溃风险，拒绝。
- **在GUI进程中直接加载contamxpy**：原生访问冲突可能终止桌面进程，也绕过受控执行边界，拒绝。
- **立即实现完整PRJ解析与回写**：缺少完整格式、未知区块和引用关系证据，风险不可接受，拒绝。
- **仅依赖样例推断格式**：不足以声称完整兼容；只允许在官方文档约束下形成可明确拒绝的最小子集。

## 待验证事项

- CONTAM 3.4 Zone区块的最小可支持语法、版本门槛和错误恢复策略。
- Zone条件字段、续行、名称编码、空白与注释的正式规则。
- 未知区块定位、原文保留和只读状态在领域模型中的表达。
- 文档读取器与ContamX结果交叉验证的字段范围和判定标准。
- 受控桌面调用、仿真进程生命周期、超时和清理的具体实现。
