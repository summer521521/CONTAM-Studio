# ADR-025：将校准平面底图作为项目绑定的应用资源管理

- 状态：Accepted
- 日期：2026-08-13

## 背景

Geometry Workbench 需要让用户参照真实建筑平面图描绘墙体、房间和开口。PNG、JPEG 与 PDF 页面是视觉参考，不是 CONTAM 语义事实，也不能因为导入文件而绕过 Studio 建筑几何的命令历史、项目身份校验或原始 PRJ 保护。浏览器直接持有用户路径会扩大文件权限；把底图编码进几何 JSON 又会造成文档膨胀、重复复制和不受控解析。

## 决策

- 底图二进制由 Rust/Tauri 通过原生文件选择器导入，并复用附件隔离与文件类型检查；WebView 只收到不透明资源 ID、SHA-256、MIME、尺寸与页数等无路径元数据。
- 资源保存到应用本地数据目录的项目身份子目录。读取时再次验证项目 session、Revision、资源 UUID、边界、普通文件形态、格式签名、大小与 SHA-256；符号链接和目录穿越关闭失败。
- `building_geometry.v1` 每个 Level 最多引用一个 `plan_underlay`。引用保存资源身份及校准状态，不保存绝对路径或二进制内容。
- 两点校准、图像原点、几何原点、旋转、透明度、显隐、锁定和 PDF 页码均使用有界整数表示，并通过既有 `geometry_edit_command.v1`、撤销历史与项目几何文档持久化。
- PNG/JPEG 在浏览器解码；PDF.js 仅在打开 PDF 底图时动态加载并在本地渲染指定页面。底图位于现有 Konva 几何图层下方，不引入第二套画布。
- 导入同时登记为未选中的项目附件。只有用户明确点击 AI 读图动作后，资源才进入既有附件选择、上下文回执与结构化几何草案链；导入本身不构成联网或上传授权。
- 删除底图命令只删除几何引用，不立即删除应用管理资源，以保证撤销与历史 Revision 仍可读取。资源清理留给独立、可审计的数据生命周期任务。

## 理由

将不可变二进制和可撤销校准状态分离，可以在不暴露路径的前提下支持真实建筑描图，也让几何文档保持小而可验证。复用现有附件边界、命令历史和 Konva 能减少平行权限与状态系统。整数坐标和比例避免跨 Rust、Python、TypeScript 的浮点序列化漂移。

## 后果

- 底图只提供尺度与定位参考，不自动生成墙体、Zone、开口、面积或 CONTAM 对象。
- 一个 Level 当前只允许一个活动底图；多图拼接、透视校正和矢量 PDF 对象提取不在本决策范围。
- PDF 运行时块体积增加，但通过语义动态导入隔离，不进入主入口或非 PDF 工作流。
- 应用本地数据会增加 `geometry-underlays` 类别；设置页只读统计与隐私说明必须持续覆盖该类别。
- 任何资源损坏、替换、身份失配或上下文过期都会使读取或保存失败，不以占位图掩盖。

## 替代方案

- 让前端保存并重复打开绝对路径：拒绝，因为扩大 WebView 文件权限且路径不可移植。
- 将 base64 数据嵌入几何文档：拒绝，因为文档膨胀并削弱资源级哈希和生命周期边界。
- 导入后自动调用 AI 识图：拒绝，因为导入本地文件不等于同意联网处理。
- 为底图建立独立撤销或 Canvas 状态：拒绝，因为会形成第二套几何事实和历史。

## 待验证事项

- Geometry Workbench 视觉集成完成后，执行正式 Tauri GUI、键盘、中英文、三主题、1280×720、1440×900 与 125%/200% 缩放截图矩阵。
- 在用户授权的隔离 fixture 上验证 PNG、JPEG、多页 PDF、资源损坏、离线重开和撤销恢复；自动测试不替代真实 GUI 证据。
- 未来若增加资源清理，必须先证明不会破坏任何可恢复 Revision，再提供独立确认与统计。
