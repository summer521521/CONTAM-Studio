# ADR-008：首个结果切片使用官方SimRead

## 状态

已接受

## 背景

SIM是ContamX生成的二进制详细结果文件。首个结果切片需要可追溯地读取Zone空气状态，同时避免在项目中重新实现未经验证的SIM二进制解析。

## 决策

从成功的Phase 4运行清单开始，校验PRJ和SIM快照及官方求解器身份，在隔离的全新后处理工作区调用同一NIST官方包中的`simread.exe`，再严格解析其节点结果文本`.nfr`。首期只支持`zone_air_state`以及温度、参考压力、空气密度和时间字段。

## 理由

官方工具提供了稳定的转换边界；运行清单绑定输入和生成物，便于复现和审计；严格文本解析的范围可独立测试。

## 后果

Phase 4运行目录和源项目保持不变，失败提取保留证据。当前不支持任意SIM、直接二进制解析、曲线、导出或其他结果类型；SimRead分发和打包仍需后续验证。

Phase 5A加固后，只有完整且哈希绑定的Phase 4成功manifest可以作为入口；manifest、PRJ和SIM在提取多个阶段复核，SimRead探测通过的二进制在正式执行前后再次核对。工作区创建后失败清单与成功清单共用同一模型，保留真实进程、流和生成物证据；工作区创建前的入口拒绝不生成伪造清单。官方NFR没有独立CONTAM日类型列，因此结果字段`day_type`为null，不作日类型推断。

## 替代方案

自行实现SIM二进制解析器，或直接从GUI读取SIM。两者均会绕过已验证的官方转换边界，本阶段不采用。

## 待验证事项

更多CONTAM版本、SimRead输出变体、长期打包和大型结果性能仍需独立Spike验证。
