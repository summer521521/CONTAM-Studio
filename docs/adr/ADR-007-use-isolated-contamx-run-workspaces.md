# ADR-007：使用隔离ContamX运行工作区

## 状态

已接受

## 背景

官方ContamX是CONTAM Studio的数值求解内核。Phase 2A的contamxpy入口需要稳态初始化且会生成文件，不能承担正式运行管理。运行必须与源PRJ、项目打开和Patch应用分离，并且结果需要可追溯到明确输入快照和求解器版本。

## 决策

- 正式运行路径使用用户明确配置的NIST官方ContamX可执行文件；CLI显式绝对路径优先于`CONTAM_STUDIO_CONTAMX`，不回退PATH、扫描磁盘或自动下载。
- 每次运行创建新的独立`run_id/workspace`，复制并哈希校验源PRJ及调用者明确列出的配套输入；ContamX只在workspace中运行。
- 使用参数数组、`shell=False`和固定cwd启动一次性进程，设置固定超时并持续排空stdout/stderr。
- 成功和失败都写入不可覆盖的结构化manifest，记录求解器版本、架构、SHA-256、输入快照、命令数组、退出码、耗时、超时、日志证据、全部生成物和源目录完整性。
- 当前成功判定要求非超时、退出码为0、源未变化且存在非空`.sim`主要结果；结果内容由后续Phase读取。

## 理由

隔离工作区让ContamX的生成物和原生失败远离源PRJ目录；哈希和manifest提供可复现的输入、求解器和输出证据；显式路径和最小参数契约避免误运行未知程序。

## 后果

- 运行记录完整但会保留独立目录和较大SIM文件，清理策略需后续设计。
- 一次性进程当前不是权限沙箱，尚未实现Windows Job Object进程树治理。
- 求解器分发、签名、许可和安装包集成仍需验证；Phase 4A只验证Windows x64。
- 运行核心不解析SIM结果、不提供GUI按钮、不支持批量或多求解器。

## 替代方案

- 直接在源PRJ目录运行：会污染用户项目并破坏追溯边界，拒绝。
- 通过contamxpy执行：其公开入口属于隔离稳态初始化检查，不是正式ContamX运行契约，拒绝。
- 常驻Python服务或HTTP服务：超出本阶段边界，暂不采用。

## 待验证事项

- 安装包中ContamX的分发、签名、许可声明和升级策略。
- Windows Job Object或等价进程树治理。
- 失败运行目录清理与长期保留策略。
- Phase 5对SIM及日志格式的只读解析。
