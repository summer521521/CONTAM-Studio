# ADR-006：采用哈希绑定、仅写副本的单字段Patch

## 状态

已接受。

## 背景

Phase 2已能严格读取经验证的CONTAM 3.4简单Zone子集，但完整PRJ格式、未知区块语义、编号重排和无损整体回写仍未解决。Phase 3需要验证第一次安全修改，不能因此重建整份PRJ、覆盖用户源文件或把有限读取能力误报为完整保存能力。

## 决策

- Phase 3A-0只支持Zone记录的`volume_m3`字段，对应19字段记录中从0开始计数的第7号`Vol`记号。
- Patch计划与应用分离。Patch绑定源文件规范化路径、SHA-256、字节大小、读取模式、文件头、Zone编号、源行号、旧记号、旧数值和绝对字节范围。
- 应用阶段重新读取并验证全部前置条件；不匹配时整体拒绝，不自动重新定位旧Patch。
- 只允许将一个已验证ASCII数字记号替换到原始字节流，未知区块通过原始字节保留，不经解析后重新生成。
- 应用目标必须是调用者明确指定且尚不存在的新`.prj`副本；源文件和任何既有输出都不得覆盖。
- 新副本完整写入并落盘后，必须验证字节公式、源快照不变、严格读取器重读结果及已解析Zone字段不变性。后置验证失败时删除新副本。
- 当前Patch不能由AI自动应用；未来GUI必须先展示Diff、取得用户确认，并复用同一领域接口。

## 理由

- SHA-256、大小和字段级前置条件可阻止计划后源文件变化或Patch篡改被静默接受。
- 单记号替换避免对未知PRJ内容进行不可靠的理解、格式化或重建。
- 新副本与独占落盘保护用户源文件和既有成果。
- 严格读取器重读与官方API隔离交叉验证共同提供语义证据，同时保持contamxpy不进入Patch运行路径。

## 后果

- 当前修改范围刻意小于读取范围，只支持一个Zone的一个体积字段。
- CONTAM编号在本切片中只是外部选择编号；稳定UUID尚未建立，因此不得将当前Patch当作长期工作区身份方案。
- Patch不能合并、排队或并发应用，也没有撤销栈。
- 输出副本可能因新记号长度不同而改变文件大小，但除目标记号外的所有原始字节必须保持一致。
- 后续扩大字段或格式支持必须增加官方证据、前置条件、字节定位和回归测试，不能泛化本决策。

## 替代方案

- **覆盖源PRJ**：可能破坏用户唯一文件，拒绝。
- **解析后重新序列化整份PRJ**：完整格式和未知区块尚未解决，拒绝。
- **只绑定路径或Zone编号**：无法发现内容变化、编号歧义或旧Patch，拒绝。
- **用字符串全局查找替换旧数值**：同一记号可能在多个字段或区块出现，无法证明目标位置，拒绝。
- **立即建立通用编辑框架**：超出当前证据和纵向切片需要，拒绝。

## 待验证事项

- 新副本写入在更多Windows文件系统、权限和安全软件环境下的行为。
- 稳定UUID、工作区快照、用户确认和撤销模型。
- 多字段或多Patch的冲突、排序和原子性规则。
- 复杂Zone记录、其他PRJ区块、编号重排和引用完整性。
- GUI与AI共用Patch审批接口时的权限、Diff和审计契约。

## 后续实现状态

Phase 3B先实现桌面人工审批和立即另存副本。Phase 3C保留本ADR的哈希绑定、单记号替换和只写新文件原则，但由Rust把Python输出写入应用拥有的不可变草稿Revision；稳定Zone UUID、线性Undo/Redo和独立“另存当前草稿”由[ADR-009](ADR-009-use-immutable-draft-revisions.md)定义。仍不支持源文件保存、多个Patch、其他字段或AI自动应用。
