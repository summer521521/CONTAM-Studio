# ADR-002：桌面宿主与Python领域核心

## 状态

已接受为首选方向，具体实现待技术Spike。

## 背景

项目需要Windows优先的桌面体验、现代双语界面、受控本地文件与进程能力，并需承载CONTAM文件处理、运行管理、结果分析和未来AI集成。技术组合必须兼顾用户体验、最小权限、Python生态适配和单人维护成本。

## 决策

首选Tauri 2作为桌面宿主，React+TypeScript作为前端，Python作为CONTAM领域逻辑、文件处理、运行管理和结果处理核心，官方ContamX作为求解器。各层通过有限、结构化、可验证的受控接口通信。

概念链路为：

```text
React GUI → Tauri桌面宿主 → 受控通信接口 → Python领域核心 → 官方ContamX
```

## 理由

- React+TypeScript适合构建复杂、双语、可审查的工作台界面。
- Tauri 2适合承载Windows桌面能力并实施显式权限边界。
- Python更贴近CONTAM相关数据处理、研究计算和未来接口生态。
- 明确分层可让GUI和AI共用领域接口，避免直接操作文件和求解器。

## 后果

- 项目需要管理Rust/Tauri、前端和Python三类工具链及其打包边界。
- 跨进程通信、错误传播、取消、日志和sidecar生命周期成为关键设计问题。
- 新依赖必须评估许可、维护状态、必要性和安装包成本。
- 当前不得把方向性决策写成已经验证的生产方案。

## 替代方案

- **Electron+Node全栈**：生态成熟，但当前未证明其资源和打包成本优于首选方向。
- **纯Python桌面GUI**：领域层简单，但复杂现代工作台体验和前端生态适配存在疑问。
- **纯Rust领域核心**：单一二进制有吸引力，但会增加领域开发成本并弱化Python生态利用。
- **Web或云优先架构**：与离线优先、本地文件和本地求解边界不符。

## 待验证事项

- Tauri与Python的通信方式、协议Schema和版本兼容。
- Python运行时及sidecar的构建、签名、更新和故障恢复。
- 前端状态与领域模型的一致性、长任务事件流和取消机制。
- Windows 10/11 64位目标机上的安装体积、启动性能和依赖兼容。
