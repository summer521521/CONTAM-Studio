# ADR-001：使用官方ContamX

## 状态

已接受。

## 背景

CONTAM Studio需要为教学与科研提供现代工作台，但数值求解本身已有官方ContamX实现并持续由其官方生态负责。重写求解器会引入数值正确性、验证、兼容和维护风险，也偏离项目价值中心。

## 决策

官方ContamX负责全部CONTAM数值求解。CONTAM Studio不重写CONTAM求解算法，只通过受控运行层发现、调用和管理官方求解器，并追踪输入快照、求解器版本和输出。

## 理由

- 复用经过专业验证的官方求解能力。
- 将有限资源集中在安全文件处理、现代交互、运行管理、结果呈现和可控AI协作。
- 保持与CONTAM格式、版本和官方生态的兼容方向。
- 避免形成难以验证的独立数值实现。

## 后果

- 产品运行能力依赖可用且受支持的ContamX版本。
- 必须处理求解器发现、版本兼容、进程隔离、失败诊断和结果追踪。
- 若未来捆绑官方二进制，必须核对来源、分发条件和第三方notice。
- Studio不能把自身描述为NIST官方产品或暗示官方背书。

## 替代方案

- **重写求解器**：因验证成本、维护风险和范围失控而拒绝。
- **只提供文件编辑、不集成运行**：不能形成目标用户所需的完整教学科研闭环。
- **抽象多个求解器**：当前没有已验证需求，属于过早复杂化。

## 待验证事项

- 首要支持的ContamX版本和跨版本兼容策略。
- 用户安装、项目捆绑或其他分发方式的取舍。
- 命令行/API调用、并发、取消、超时和错误报告能力。
- 官方主体及独立组件的准确许可和notice要求。
