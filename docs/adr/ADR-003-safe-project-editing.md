# ADR-003：安全项目编辑

## 状态

已接受。

## 背景

PRJ完整格式、无损解析、无损回写、未知区块保留、编号重排和复杂引用关系尚未解决。直接修改原始文本或以CONTAM显示编号作为内部身份，可能破坏工程文件、丢失未知内容或产生隐蔽引用错误。AI写入会进一步放大这些风险。

## 决策

- 原始PRJ默认不覆盖，编辑发生在草稿、内存模型或明确副本中。
- 内部对象使用稳定UUID；CONTAM原始编号只作为外部格式编号或显示信息。
- 未知或暂不支持的内容不得静默丢失；无法可靠保存时保持只读。
- 所有修改表示为结构化Patch，应用前显示Diff并默认要求用户确认。
- Patch应用前后执行确定性结构和引用验证。
- 保存与运行使用明确快照，支持撤销、回滚和追踪。
- GUI与AI通过同一领域接口修改项目，均不得直接编辑原始PRJ。

## 理由

- 保护用户唯一版本的真实工程文件是首要约束。
- Patch和Diff使人类能够理解、拒绝或批准修改。
- 稳定UUID可将内部身份与可能重排的外部编号解耦。
- 快照可把运行结果可靠绑定到具体输入。
- 只读降级比不可靠保存更诚实、更安全。

## 后果

- 首版可编辑范围将小于可读取范围。
- 需要额外建设草稿、Patch Schema、Diff、验证、快照和回滚机制。
- 无损能力必须由真实样例和回归证据支持，不能仅凭解析成功声明完成。
- 测试必须使用夹具或副本，不能修改用户唯一文件。

## 替代方案

- **直接文本编辑原始PRJ**：无法稳定保护未知区块和复杂引用，拒绝。
- **保存时整体重新生成PRJ**：在完整格式未解决前容易静默丢失内容，拒绝。
- **以CONTAM编号作为内部主键**：编号可能重排，无法保证稳定身份，拒绝。
- **AI获批后直接写文件**：仍绕过统一验证与快照链，拒绝。

## 待验证事项

- PRJ完整区块和记录语法。
- 未知区块、注释和格式信息的保留粒度。
- 编号重排规则、复杂引用图和跨区块完整性检查。
- 语义等价、未修改内容保真和官方工具兼容的测试判据。
- Patch Schema、Diff呈现和快照存储的具体方案。
