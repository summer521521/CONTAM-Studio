## 1.一句话契约

CONTAM Studio v0.1使具有建筑环境、暖通或室内空气品质基础知识，但不具备软件开发或PRJ文本编辑能力的学生或研究生，在Windows 10/11 x64标准用户环境中，使用教师提供且Studio明确判定为受支持的CONTAM案例，在无需Node、Rust、系统Python、Codex和网络的条件下，通过官方ContamX/SimRead完成一次受控单变量前后对照实验，不覆盖原始PRJ，并导出可追溯的新PRJ副本和比较证据。

## 2.用户优先级

### 主Persona

高年级本科生或研究生：

- 接收教师准备的案例和实验问题，不在Studio内从零建立复杂模型。
- 理解Zone、参数、单位和结果等专业概念，但不应理解manifest、哈希、Python环境、命令行或PRJ内部编号。
- 使用简体中文或英文，在Windows标准用户权限下完成实验。
- 需要清楚区分原始项目、草稿Revision、基线运行、变体运行和导出证据。

### 次要Persona

教师或案例准备者：

- 准备来源明确、已进入兼容矩阵的案例和实验问题。
- 检查学生提交的Diff、输入身份、求解器身份、A/B结果和导出证据。
- v0.1不承诺教师能在Studio内从零创建或完整编辑CONTAM模型。

### 设计伙伴而非v0.1目标

复杂科研项目使用者可参与反馈，但其批量场景、任意真实PRJ、复杂风管、控制系统和多污染物工作流不能反向扩大v0.1范围。这些需求作为v0.2及以后输入。

## 3.旗舰任务包络

v0.1只承诺一个旗舰任务：**教师案例中的受控单变量前后对照实验**。

1. 用户以标准权限安装并离线启动Studio，不需要开发工具。
2. 用户打开教师提供的案例，Studio给出明确的受支持或整体拒绝结论，并显示原始文件受保护。
3. 用户对基线Revision运行官方ContamX，并读取一种严格验证的结果。
4. 用户在草稿中人工修改一个受支持字段，查看结构化Diff后明确确认。
5. 用户验证Undo/Redo，原始PRJ字节保持不变。
6. 用户运行修改后的Revision。
7. 用户选择基线与变体；只有基线项目、对象UUID、结果类型、单位和时间网格全部兼容时才允许比较，v0.1不插值。
8. 用户导出一个新的PRJ副本，以及包含Revision、求解器版本、单位、A/B身份和差值的比较CSV。
9. 用户可以选择使用只读AI解释已披露上下文，但AI不计入核心任务完成率，也不能补偿基础GUI缺失。

精确案例、可写字段、结果类型和比较问题由`SCENARIO-01`根据Alpha观察冻结。当前`volume_m3 → zone_air_state → CSV`只作为Developer Alpha技术代理任务，不得在用户证据前宣称为最终教学或科研旗舰场景。

如果`SCENARIO-01`选择CO2、污染物、气流或任何非现有`zone_air_state`结果，必须先在执行任务书中新增独立的结果类型纵向任务，覆盖官方样例、SimRead输入、严格Python解析、协议、Rust验证、React呈现、导出和GUI验收。不得把该工作暗含在`DOMAIN-03`、`RESULT-02/03`或比较任务中。

## 4.当前能力与目标的边界

| 能力 | 当前Developer Alpha | v0.1目标 |
|---|---|---|
| 项目读取 | 严格简单Zone子集 | 只支持旗舰案例所需、证据充分的明确兼容矩阵；不承诺完整PRJ |
| 人工修改 | 单个Zone的`volume_m3` | 一个由`SCENARIO-01`批准的字段，复用同一Patch审批链 |
| 草稿 | Revision、Undo/Redo、另存副本 | 增加切换和退出保护，统一文件输出所有权 |
| 运行 | 单次官方ContamX运行 | 工具身份冻结、取消、进程树收口、配套输入和可信历史 |
| 结果 | 当前Zone的温度、参考压力、空气密度和CSV | 一种与旗舰问题匹配的结果、受控存储、后端统计和严格A/B比较 |
| 分发 | 仓库`.venv`和环境变量 | 干净Windows无需Node、Rust或系统Python即可使用 |
| AI | 可选只读助手，当前状态见能力矩阵 | 始终可选；无AI、无Codex和无网络时P0核心任务完整 |
| 完整PRJ | 未实现 | 明确非目标；矩阵外项目整体拒绝，不显示部分可信结果 |

## 5.P0产品范围

P0表示v0.1不可缺少的产品能力。

### 安装与离线

- Windows 10/11 x64标准用户可安装、启动、覆盖安装和卸载。
- 用户不需要Node、Rust、项目源码、系统Python或命令行配置。
- 除用户主动启用的AI外，旗舰任务全程可离线完成。
- Python worker由安装包提供；不得回退到PATH或依赖全局Python。
- ContamX/SimRead必须通过经用户批准的捆绑方案或原生GUI配置方案交付，用户不得编辑环境变量。

### 兼容与数据安全

- 每个受支持案例均有来源、版本、哈希、布局和使用权证据。
- 矩阵外或语义不明的项目整体拒绝，并提供可操作诊断；不能返回部分可信项目。
- 原始PRJ默认且实际不覆盖；所有修改发生在草稿、内部Revision或新副本。
- 打开其他项目和退出应用前保护未导出草稿。
- 输出使用统一的不可覆盖、可证明所有权和commit-last协议。
- 草稿、运行和结果具有有界生命周期和用户可理解的清理入口。

### 修改、运行与结果

- 只支持一个场景、一个人工可写字段、一个结果类型和一个比较问题。
- 人工修改必须经过计划、Diff、确定性验证、用户确认、Revision、Undo/Redo和另存。
- 官方ContamX/SimRead实际执行字节、输入Revision、配套文件、运行和结果完整绑定。
- 用户可取消运行；超时、取消和应用退出必须有界收口整个进程树，不残留本次工具进程。
- 运行历史和结果存储由Rust控制，WebView不能提供路径、manifest或样本。
- A/B比较由可信后端执行；身份、单位或时间网格不一致时整体拒绝。
- PRJ副本和比较CSV均为新文件、不可覆盖，并携带足够身份和单位证据。

### 界面与理解

- 中英文核心流程、专业术语、单位、错误和教学材料语义一致。
- 100%至200% Windows缩放、最小支持窗口和纯键盘核心流程可操作。
- 未实现功能隐藏或明确禁用，不以模拟项目、假结果或阶段术语误导用户。
- 用户能区分原始文件与草稿、基线与变体、确定性证据与AI解释。

### AI边界

- AI默认未连接；本地档案默认关闭。
- AI只能解释用户预览并确认披露的结构化上下文。
- 无AI时全部P0能力可用。
- AI Patch、自动运行、任意工具和历史自动重放不属于v0.1。

## 6.P1产品范围

P1只能在P0门禁稳定后推进，不能延迟P0修复或扩大领域模型：

- 现有Codex只读解释和可选本地档案；若真实GUI门禁未通过，可在v0.1隐藏，不得阻止核心发布。
- 使用相同对象、字段和结果契约的第二个教学案例，不因此增加新的领域语义。
- 教师审阅摘要、术语表和非阻断诊断改进。
- 不改变科学语义的图表、性能和易用性优化。

P0/P1在本节表示产品优先级。缺陷严重度另行处理：源文件损坏、错误接受不支持项目、结果或身份错绑、求解器残留、未披露联网和伪成功均为发布阻断P0缺陷；需要开发者接管核心任务、普通错误无法恢复、关键单位或双语缺失属于P1缺陷，必须修复或由用户明确批准为公开已知限制。

## 7.明确非目标

- 完整PRJ解析、任意项目兼容、完整模型编辑或源文件原位保存。
- 多字段、多Patch事务、批量运行、参数扫描、优化和复杂科研工作流。
- 超出最终旗舰场景所需的对象和结果类型。
- 跨重启草稿恢复；v0.1只要求切换和退出保护以及显式导出。
- 复杂风管和控制系统完整编辑、CAD、BIM、其他求解器或通用仿真平台。
- macOS、Linux、云同步、账户、多用户协作、企业权限和插件SDK。
- 自动更新；v0.1可以提供手动、可追溯升级路径。
- AI Patch、自主运行、任意工具、其他AI后端或自动恢复聊天。
- 将本地AI档案自动加入新的模型上下文。

## 8.量化门禁

### 不可妥协红线

- 零原始文件覆盖或用户数据损坏。
- 零静默语义错误、项目/Revision/运行/结果错绑和伪成功。
- 零未披露联网或AI历史自动重放。
- 受支持语料的结果、比较和导出100%符合冻结的确定性参考。
- 发布时P0缺陷为零；P1缺陷均已修复或由用户批准为公开已知限制。

### Alpha门禁

- 3至5名参与者，主Persona占多数，并至少包含1名教师或案例准备者。
- 使用当前`volume_m3 → zone_air_state → CSV`代理任务测试交互和证据链，不把它冒充最终旗舰场景。
- 至少80%参与者无需开发者接管鼠标、键盘或命令行即可完成；最多允许1次预先定义的中性提示。
- 至少80%参与者能正确说明原始文件是否变化、修改字段及单位、结果来源和当前能力限制。
- 零P0事件；每个P1问题均有复现步骤、Owner和处置结论。
- Alpha只采集完成时间基线，不提前设定Beta时间阈值。

### Beta门禁

- 5至10名主Persona完成最终旗舰任务，并由至少1名教师审阅导出证据。
- 至少80%主Persona独立完成核心任务。
- 根据Alpha基线冻结Beta时间阈值；未经Alpha证据不得在实现任务中任意修改。
- 至少80%主Persona能正确回答原始文件、修改量、A/B身份、单位和解释限制五项理解题。
- Windows 10和11干净标准用户矩阵中的安装、离线启动、核心任务、覆盖安装和卸载全部通过。
- 满足全部不可妥协红线。

本项目不加入隐藏遥测。完成率、提示、时间、错误、理解题和访谈结果由观察者使用明确表格记录，不自动上传。

## 9.Alpha观察提纲

观察者不得代替参与者操作。测试前只提供最终用户会获得的安装包、案例和教学材料。

记录以下事件：

1. 安装、首次启动和工具状态是否需要解释。
2. 用户是否理解案例兼容结论和原始文件保护状态。
3. 用户能否找到基线运行、修改、Diff、Undo/Redo、变体运行、比较和导出入口。
4. 用户在哪一步请求帮助，帮助属于产品缺口、案例教学还是专业知识。
5. 错误是否可恢复，是否需要开发者、命令行或文件管理器介入。
6. 用户如何解释单位、A/B差异、结果限制和AI回答边界。
7. 用户真正希望回答的一个教学或科研问题，以及当前代理任务为何不足。

访谈只收集以下决策输入：

- 哪个单变量问题最有教学或研究价值。
- 教师能否提供来源和使用权明确的自包含案例。
- 哪一个字段、结果和比较问题足以形成完整练习。
- 哪些不支持内容应整体拒绝，哪些只需只读显示。
- 用户是否需要AI；若需要，AI解释何处有价值，何处必须依赖确定性证据。

## 10.旗舰场景选择方法

`SCENARIO-01`只能从满足全部硬门的候选中选择：

1. 案例来源、版本、哈希、使用权和再分发权明确。
2. 案例属于有官方证据支持的CONTAM版本和布局。
3. 任务恰好需要一个可写字段、一个结果类型和一个比较问题。
4. 官方工具可重复产生非零且可解释的前后差异。
5. 不要求完整AST、编号重排、多Patch、批量运行、复杂控制或AI写入。
6. 所需配套输入可显式、有界且带哈希绑定。
7. 至少60% Alpha主Persona认可其价值，且至少1名教师确认变量、单位和解释边界成立。
8. 根据Alpha时间基线，任务可在一次正常教学练习内完成。

满足硬门后按以下顺序选择：用户价值证据、科学可解释性、格式与工具证据、安全和可逆性、实现语义面、案例分发可行性。多个候选接近时，默认选择新增对象、字段、结果和配套输入最少的候选。最终选择必须由用户确认，模型不能单方面冻结。

教室CO2、污染物浓度或气流比较可以作为候选，但在Alpha证据、官方结果契约和新增结果纵向任务明确前均不是v0.1承诺。

## 11.后续用户决策门

| 决策 | 当前产品要求或推荐默认 | 最迟门禁 |
|---|---|---|
| 精确案例、字段、结果和比较问题 | Alpha后按本文件方法由用户选择 | `SCENARIO-01` |
| Python运行时 | 安装包提供冻结worker，不依赖系统Python | `DIST-01` |
| ContamX/SimRead | 许可与Notice核验通过后优先捆绑固定版本；否则使用Rust原生受控配置 | `DIST-01` |
| Codex | 外部、可选、用户主动连接，不作为核心前置 | `DIST-01` |
| Studio许可证 | 未决定；不得由模型选择 | `BETA-01`前 |
| 案例和第三方Notice | 逐项核验，无证据则不分发 | `DOMAIN-01`,`BETA-01` |
| 签名、更新、卸载数据 | 用户批准唯一策略和恢复方案 | `DIST-01` |
| AI是否显示在v0.1正式界面 | 真实GUI门禁通过则保留，否则隐藏 | `BETA-01` |

在Studio许可证、官方工具再分发和第三方Notice未由用户确认前，可以进行不发布二进制的分发Spike，但不得发布User Beta或正式安装包。

## 12.变更控制

- 低思考模型不得修改主Persona、旗舰任务包络、P0、红线或量化门禁。
- Alpha证据只能在`SCENARIO-01`中冻结精确案例、字段、结果和时间阈值，不能顺手扩大完整PRJ范围。
- 新增结果类型、运行时依赖、工具捆绑、许可、数据迁移、Tauri权限或AI写入必须新开任务并按对应高风险门禁处理。
- 任何范围变更必须同时说明用户证据、能力矩阵影响、任务依赖、退出条件和明确删除的旧范围。
